# Silent Pix Desktop

Tauri 2 desktop shell using the existing SolidJS UI in `apps/web`. The desktop app does not start the backend or ComfyUI.

## Structure

```text
apps/desktop/
  package.json
  Cargo.toml
  Cargo.lock           Generated by Cargo
  build.rs
  tauri.conf.json
  capabilities/
  icons/
  src/                 Rust source files only
  script/
    dev-wsl.bat
    link-wsl.bat
    link-wsl.ps1
  target/              Local native build outputs
```

The Tauri project root is `apps/desktop`. Frontend build hooks run from the monorepo root; the bundled UI comes from `apps/web/dist`.

## Prerequisites

Install the [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/) on the operating system running the desktop app: Rust, the platform build tools, and WebView dependencies. Windows development requires the MSVC Rust toolchain, Microsoft C++ Build Tools, and WebView2.

Install Node.js and pnpm `10.15.0` on that operating system as well. Running Tauri inside WSL builds a Linux app; use Windows tooling for a native Windows app.

## Development on one operating system

From the repository root:

```sh
pnpm install
pnpm dev:desktop
```

This builds the web workspace dependencies, starts Vite at `http://127.0.0.1:1420`, and launches Tauri. An occupied port causes startup to fail instead of selecting another port.

Start the backend separately. The development API and WebSocket proxy defaults to `http://127.0.0.1:3070`. To use another backend:

```sh
SERVER_URL=http://192.168.1.10:3070 pnpm dev:desktop
```

In Windows PowerShell:

```powershell
$env:SERVER_URL = 'http://192.168.1.10:3070'
pnpm.cmd dev:desktop
```

`SERVER_URL` configures the Vite development proxy only. HTTPS domains are supported, but Cloudflare Access authentication is not integrated yet.

## WSL frontend with a native Windows desktop

Keep frontend development in WSL and compile the native shell in a local Windows directory. The setup links source files from WSL while keeping `node_modules`, `target`, `gen`, and `tauri.wsl.conf.json` on Windows.

Run the following in Windows PowerShell. Replace every placeholder with your own distribution name (`wsl -l -q`), WSL repository path, and Windows destination. Use a new or empty destination; the setup refuses to overwrite existing files.

```powershell
$desktopSource = '\\wsl.localhost\<distribution>\<path-to-repository>\apps\desktop'
$desktopDestination = 'C:\<development-directory>\silent-pix-desktop'
& "$desktopSource\script\link-wsl.bat" -Source $desktopSource -Destination $desktopDestination
```

Creating symbolic links requires Windows permissions. If denied, run setup from an elevated PowerShell terminal. The script does not change system settings. Keep your previous copied shell until the linked one works.

`src`, `script`, `capabilities`, `icons`, `Cargo.toml`, `build.rs`, `tauri.conf.json`, and `package.json` are linked. An existing `Cargo.lock` is copied, not linked; review and synchronize lockfile changes explicitly after dependency updates. Do not link the entire desktop directory or its build outputs.

Start the backend in one WSL terminal if needed:

```sh
pnpm dev:server
```

Start Vite in another WSL terminal:

```sh
pnpm exec turbo run build '--filter=@silent-pix/web^...'
pnpm --filter @silent-pix/web dev:desktop
```

Set `SERVER_URL` on the Vite command when using a remote backend. Confirm that a Windows browser can open `http://127.0.0.1:1420`.

In the same Windows PowerShell session:

```powershell
Set-Location -LiteralPath $desktopDestination
pnpm.cmd install
.\script\dev-wsl.bat
```

You can also double-click `script/dev-wsl.bat`. It creates `tauri.wsl.conf.json` if missing, disables the frontend startup hook, and connects to the Vite server already running in WSL. On failure, it keeps the console open.

Existing WSL configuration settings are preserved.

The equivalent command, after the configuration exists, is:

```powershell
pnpm.cmd tauri dev --config tauri.wsl.conf.json
```

Keep both development processes running. UI changes in WSL update through Vite. Rust changes are visible through the links. File watcher notifications across WSL may not trigger reliably; restart the desktop command if a Rust change does not rebuild. Closing the desktop does not stop the backend.

The standalone Windows linked directory supports this development workflow only; the production build hooks require the complete monorepo.

## Validation and packaging

From the complete repository:

```sh
pnpm check
pnpm build
pnpm --filter @silent-pix/desktop check:native
pnpm build:desktop
```

- `check` and `build` validate the TypeScript workspace and Web UI. `check:native` checks Rust separately.
- `build:desktop` builds the shared UI and packages Tauri for the host operating system.
- Native outputs are in `apps/desktop/target/release/`; installers are under `bundle/`.
- With a backend available, check Generate, Workflow, Compare, image loading, and WebSocket reconnection.
- With the backend unavailable, check that the window opens and displays the existing connection or query error state.

## Current limitations

- Packaged builds currently provide the UI shell only. REST, image URLs, and WebSocket connections still use the current origin; production remote connectivity is not wired yet.
- Server selection, authentication, native file access, tray integration, and automatic updates are not implemented.
- Icons use the Tauri scaffold defaults.
- The first native build generates a local `Cargo.lock`; copy it back to the repository and include it in version control after platform validation.
- The Windows symbolic-link workflow and native compilation need validation on Windows; they cannot be verified in the current Linux environment.
