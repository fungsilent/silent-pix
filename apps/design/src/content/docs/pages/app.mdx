## Header · 頁面與平台

App 最上方 36px 的全域列，同時是視窗的標題列：品牌名、模式選單、Tools 選單、拖曳區、Issue chip、服務狀態燈與 Settings 鈕；Desktop 的 Windows／Linux 另有視窗控制。所有頁面共用同一條，頁面本身不畫 header。

<Rules component="app-header" part="pages">

<ul class="ds-rules">
<Rule component="app-header" id="layout-order">左到右固定順序：（macOS 的原生視窗鈕）→ 品牌名「Silent Pix」→ 模式選單 → Tools 選單 → 拖曳區（彈性空白）→ Issue chip（有問題時）→ 服務狀態燈 → Settings 鈕 →（Windows／Linux 的視窗控制）。列高 36px（`h-9`），比面板的 48px Bar 薄，讀起來是標題列而不是另一條工具列；控制項維持 28px，上下各留 4px。底線 `border-line-subtle`，項目間距 4px。App 圖示尚未定稿，先用品牌名。</Rule>
<Rule component="app-header" id="title-bar">Desktop 不用作業系統的標題列，Header 就是標題列：拖曳區與品牌名等非控制項的空白可以按住拖動視窗，雙擊放大／還原；按鈕與選單照常點擊。Windows／Linux 在最右側畫三顆 46×36px 的視窗控制（縮小、放大／還原、關閉），hover 用 `bg-hover`，關閉鈕 hover 用 `bg-danger text-on-stage`。macOS 保留原生的三顆視窗鈕（由系統繪製；藍圖中的紅黃綠只是示意系統顏色，不是產品 token），Header 左側讓出位置，並把原生鈕垂直置中在 36px 的列上。Web 沒有視窗控制，拖曳區只是空白。</Rule>
<Rule component="app-header" id="mode-menu">模式選單的觸發鈕顯示目前（或最後使用）的模式圖示與名稱加 ▾，展開後列出 Generate／Compare／Workflow 三項（選單樣式見 L0 Menu），目前模式用 selected 樣式。觸發鈕平常是 ghost，展開時 `bg-selected text-fg`；目前頁面是模式時文字 `text-fg`，在 Tools 或 Settings 頁時 `text-fg-muted`。</Rule>
<Rule component="app-header" id="tools-menu">Tools 選單放工具類頁面，目前只有 Image Metadata；新增工具頁才加項目，不分組。觸發鈕只有文字「Tools」加 ▾；目前在工具頁時文字 `text-fg`，選單內那一項用 selected 樣式。</Rule>
<Rule component="app-header" id="settings">Settings 是 `size-7` 的齒輪 ghost 鈕；目前在 Settings 頁時維持 `bg-selected text-fg`，再按一次關閉 Settings、回到進入前的頁面；沒有可回的頁面時回到最後使用的模式（預設 Generate），尚未設定 endpoint 時則維持在 Settings。主題切換在 Settings 的 Appearance 卡，不放 Header。</Rule>
<Rule component="app-header" id="narrow">視窗變窄時依序收縮：服務狀態只留燈、模式選單只留圖示；仍不夠時才隱藏品牌名。不換行、不橫向捲動。</Rule>
</ul>

</Rules>

## Header · 服務狀態

服務狀態收成一顆燈：全部正常只有綠燈，出問題才加文字，細節在點開的 popover。

<Rules component="app-header" part="service">

<ul class="ds-rules">
<Rule component="app-header" id="service-status">服務狀態燈：Server／DB／Comfy 全部正常時是 `size-7` ghost 鈕內一顆 8px 的 `bg-success` 光暈點，沒有文字。有服務斷線時變成 `bg-danger/12 text-danger-fg` 的鈕，6px `bg-danger` 點加斷線的名稱（例如「Comfy down」，兩個以上時「2 down」）；從未連上時是 muted 點加「Connecting」。</Rule>
<Rule component="app-header" id="status-popover">點狀態燈展開 `w-60` 的 Popover（靠右緣 bottom-end，見 L0 Popover）：Server／DB／Comfy 各一列，6px 狀態點、名稱、右側狀態文字（Connected／Not reachable／Unknown，一律 `text-fg-muted`；斷線由紅色狀態點表示）；下方分隔線後是 soft「Recheck」重新檢查。</Rule>
<Rule component="app-header" id="status-source">Server 跟即時連線走。DB／Comfy 在即時連線首次建立前先用一次查詢結果墊著，之後只認即時狀態；斷線時 DB／Comfy 一律轉 unknown，不沿用最後一份結果。從未連上過時三段都是 unknown。</Rule>
</ul>

</Rules>

## 啟動失敗

App 啟動時就出錯（例如讀不到設定），整個視窗只顯示一個置中的 StatusMessage，沒有 Header。

<Rules component="app-startup">

<ul class="ds-rules">
<Rule component="app-startup" id="error">用 regular StatusMessage 的 load-error 置中在 `bg-canvas` 上：一句 muted 訊息，按鈕是「Reload」（重新載入整個 App）。不用紅字，不顯示原始例外訊息以外的技術細節。</Rule>
</ul>

</Rules>
