<Rule component="workflow-opening-screen" id="opening-screen">沒有任何 workflow（也沒有建立中的 draft）時沒有三欄，整個工作區是開啟畫面，同 Metadata 尚未開檔：L0 StatusMessage regular guide，Workflow 圖示方塊、標題「No workflows yet」、一句說明 workflow 是什麼、accent「Add workflow」（Plus 圖示）。</Rule>

</ul>

</Rules>

#### 列

<ul class="ds-rules">
<Rule component="workflow-item" id="row">整列可點，只放名稱；高 32px、`rounded-md px-2.5`、名稱 `text-xs` 單行截斷。</Rule>
<Rule component="workflow-item" id="colors">未選取為 `text-fg-secondary`，hover 換 `bg-elevated`；選取用 L0 selected 樣式（`bg-selected text-fg`），hover 不再變色。</Rule>
<Rule component="workflow-item" id="archived">封存且未選取改 `text-fg-muted`；被選取後與一般選取列完全相同，封存身分由 workflow-detail 的「Read-only · archived」交代。</Rule>
<Rule component="workflow-item" id="badge">只有選取中的列（或建立中的 draft）會帶 L0 Badge neutral：建立中顯示「Draft」，已存在且有未儲存修改顯示「Unsaved」。其他列一律不帶 badge。</Rule>
<Rule component="workflow-item" id="untitled">Draft 名稱空白時顯示「Untitled」；名稱即時跟著 workflow-info 的輸入更新。</Rule>
</ul>

<Rules component="graph-editor">

<ul class="ds-rules">
<Rule component="graph-editor" id="column">Workflow 頁中欄，佔滿 workflow-list 與 workflow-detail 之間的寬度；`bg-surface`、右側 `border-r border-line`。頂端 L0 Bar 標題「API JSON」，編輯區直接接在 Bar 下方，不另放欄位 label。</Rule>
<Rule component="graph-editor" id="single-editor">編輯的是 ComfyUI API 格式的 JSON 文字，不是節點圖。整塊是單一文字編輯器：左側固定的行號 gutter 與 field gutter，右側為內容；水平捲動時 gutter 保持不動。</Rule>
<Rule component="graph-editor" id="surfaces">內容區 `bg-elevated`、gutter 降到 `bg-surface` 才分得開；行高 24px、12px monospace，行號 gutter 42px；field gutter 寬度剛好放下最長的綁定 field 標籤，沒有任何綁定時整欄不顯示。兩者各以 `border-line-subtle` 右框分隔。</Rule>
<Rule component="graph-editor" id="bound-lines">被 mapping 綁定的 input 行：field gutter 沿用 Mapping 的欄位標籤（`text-code-string`，綁定失效時 `text-danger-fg`），整行底色 `bg-workflow-bound-soft`／失效為 `bg-workflow-broken-soft`。</Rule>
<Rule component="graph-editor" id="tokens">Token 色只有六種：第一層 key（node id）`text-accent-fg`，其他 key `text-fg`，字串 `text-code-string`，數字 `text-code-number`，`true`／`false`／`null` `text-code-literal`，標點與其他 `text-fg-muted`。</Rule>
<Rule component="graph-editor" id="paste-format">貼上壓縮成一行的 JSON 時自動以 2 空白縮排重排，行號與標記才對得上；一般打字不重排。空文件顯示 placeholder「Paste the ComfyUI API JSON here.」。</Rule>
<Rule component="graph-editor" id="loading-read-only">有 workflow 時一定有選取，沒有「未選取」狀態（沒有 workflow 時見 Opening screen）。載入中以直角 skeleton 蓋滿編輯區且不可互動。封存、已刪除或 Server 不可用時內容唯讀，仍可選取及複製原文。</Rule>
<Rule component="graph-editor" id="issues-elsewhere">JSON 無法解析、格式不是 API graph（例如 UI workflow 格式）等問題不在編輯器內標示，而是進 Header 的 Issue chip（來源 Graph）。</Rule>
</ul>

</Rules>

<Rules component="workflow-detail">

#### 詳細欄

<ul class="ds-rules">
<Rule component="workflow-detail" id="column">Workflow 頁最右欄，固定寬 380px（同 Generate 的 task-detail）、`bg-surface`；頂端 L0 Bar 標題「Detail」，下方可捲動內容（`px-4 pb-5 gap-3`）依序放 workflow-info、分隔線、workflow-mapping。Graph 不屬於本欄，在中欄 graph-editor。</Rule>
<Rule component="workflow-detail" id="three-columns">頁面三欄並排：workflow-list（200px）→ graph-editor（彈性）→ workflow-detail（380px）；整頁最窄 940px，更窄時整頁水平捲動而不擠壓欄寬。</Rule>
<Rule component="workflow-detail" id="bar-actions">Bar 右側（有選取時）只有 Save。Save 是 bar 尺寸的 accent solid、semibold；沒有修改、儲存中、載入中、版本衝突、名稱空白、graph 無法解析或 mapping 有問題時停用（`opacity-60`），儲存中文案換成「Saving」。</Rule>
<Rule component="workflow-detail" id="issue-chip">名稱必填、graph 解析、mapping 失效與儲存失敗都進 Header 的 Issue chip，來源分別標 Name／Graph／Mapping／Save；Workflow detail 本身不放 chip，只靠欄位標記（例如 missing Badge）與 Save 停用表示。清單讀取失敗由 Opening screen 顯示。</Rule>
<Rule component="workflow-detail" id="archived">封存的 workflow 整欄唯讀：Save 換成 muted 文字「Read-only · archived」，workflow-info 名稱與 workflow-mapping 全部 disabled。</Rule>
<Rule component="workflow-detail" id="deleted">選取的 workflow 被其他客戶端刪除時，有未儲存修改就保留草稿。Bar 顯示「Read-only · deleted」，內容提示可到 API JSON 複製草稿，並保留唯讀的 Info 與 Mapping。這個狀態沒有 Save、Delete 或 Retry。沒有未儲存修改時選取清單第一項，清單為空時回到 Opening screen。</Rule>
<Rule component="workflow-detail" id="loading">載入中 Bar 保留、Save 停用，內容各區塊以 skeleton 遮罩並不可互動（見 workflow-info、workflow-mapping 的 loading）。</Rule>
<Rule component="workflow-detail" id="load-error">選取的 workflow 讀取失敗時，內容整塊換成置中的 L0 StatusMessage regular load error「Failed to load workflow.」＋ Retry；Bar 只留標題，右側不放任何動作。</Rule>
<Rule component="workflow-detail" id="unavailable">Server 不可用時整欄唯讀，組法同封存：workflow-info 與 workflow-mapping 用各自的唯讀狀態，Bar 右側保留 Save 但停用。</Rule>
<Rule component="workflow-detail" id="pending">封存或刪除進行中時 Save 停用，workflow-info 的破壞性按鈕顯示進行中（見 workflow-info 的 pending）。</Rule>
</ul>

#### Info

<ul class="ds-rules">
<Rule component="workflow-info" id="position">位於 workflow-detail 最上方，沒有自己的區段標題；結構對應 task-info：identity 在上、破壞性動作放最下面。</Rule>
<Rule component="workflow-info" id="rows">兩列 label／value grid（label 欄 74px、`gap-3`）：Name 是 L0 inline editable（文字框＋鉛筆按鈕），Revision 是唯讀文字。</Rule>
<Rule component="workflow-info" id="name-trim">名稱提交時去頭尾空白並截到 120 字；空值顯示 placeholder「Untitled」。</Rule>
<Rule component="workflow-info" id="revision-badge">Revision 旁的 Badge：新建 draft 顯示「Draft」、有未儲存修改顯示「Unsaved」，一律 neutral。新建（尚未存過）顯示「—」並改 muted 色，且不出現破壞性按鈕。</Rule>
<Rule component="workflow-info" id="destructive-button">破壞性按鈕是滿寬的 L0 Button soft danger，文案依用量：仍有 task 使用且未封存 →「Archive workflow」；沒有 task 使用或已封存 →「Delete workflow」。點下後一律先開確認 dialog。</Rule>
<Rule component="workflow-info" id="archived-name">封存後名稱改成 disabled 外觀，不可編輯；刪除鈕仍可用。Server 不可用時名稱同樣 disabled，破壞性按鈕停用（L0 Button disabled：`opacity-60`）。</Rule>
<Rule component="workflow-info" id="pending">確認 dialog 送出後、結果回來前，此處的破壞性按鈕以 L0 Button disabled 停用、文案不變；進行中文案（「Archiving...」／「Deleting...」）只出現在確認 dialog 的確認鈕上。</Rule>
<Rule component="workflow-info" id="loading">載入中每個 value（名稱、revision、按鈕）各自蓋上 skeleton 遮罩，label 保留，整區不可互動。</Rule>
</ul>

#### Mapping

<ul class="ds-rules">
<Rule component="workflow-mapping" id="position">位於 workflow-detail 中 workflow-info 下方，把每個 generator field 綁到 graph 的 node 與 input。依分組拆成四個區段，固定順序 Sampler、Latent、Prompt、Other；每段以 L0 section title 起頭，段與段之間的分隔同 task-detail 的區段（`my-1 border-t border-line-subtle`），沒有另外的「Mapping」總標題或欄名列。</Rule>
<Rule component="workflow-mapping" id="field">每個 field 照 task-config 的欄位排法：field 標籤在上（跟隨介面語言），下面一列兩個等寬 Select：Node、Input，`gap-2`（同 task-config 的成對欄位）。不合併成一個「node › input」選擇器：L0 Select 不分組，合併後的平面清單在節點多的 graph 會太長。</Rule>
<Rule component="workflow-mapping" id="node-options">Node 選項顯示為「nodeId · 標題」，清單第一項永遠是「Not bound」。未綁定時 Input 位置是虛線空框（`border-dashed border-line`），不是停用的 Select。</Rule>
<Rule component="workflow-mapping" id="broken-binding">綁到 graph 中已不存在的 node 或 input 時，下拉仍顯示原值並加 danger Badge「missing」，讓使用者看得到原本綁的是什麼；node 失效時 input 一併標 missing。這些問題同時列在 Header 的 Issue chip，Save 停用。</Rule>
<Rule component="workflow-mapping" id="auto-input">換 node 時自動選該 node 的第一個 input，避免留下必定失效的綁定。</Rule>
<Rule component="workflow-mapping" id="read-only">Archived workflow 或 Server 不可用時整區唯讀：每個 Select 改 disabled 外觀，佈局不變。</Rule>
<Rule component="workflow-mapping" id="loading">載入中同 task-config：區段標題與 field 標籤保留，Node 與 Input 兩格各自蓋上 28px 的 skeleton 遮罩。</Rule>
</ul>

</Rules>

<Rule component="workflow-confirm-dialog" id="close-on-success">失敗時 dialog 保持開啟並在 footer 顯示錯誤；成功才關閉。</Rule>
<Rule component="workflow-confirm-dialog" id="archive-or-delete">Workflow 仍有 task 使用時只能封存（說明寫出使用數，封存後離開 generate 選單、既有 task 照常）；沒有 task 使用才真正刪除；已封存的 workflow 要等所有 task 都不再使用才刪得掉，說明寫出剩下幾個。</Rule>
</ul>

</Rules>
